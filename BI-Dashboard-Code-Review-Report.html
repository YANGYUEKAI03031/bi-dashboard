5. 代码质量问题

🔴 严重问题 (Critical)

明文密码存储与验证
User.password 存储明文，auth.py 登录直接 user.password == form.password 对比。security.py 中的 bcrypt 哈希函数 verify_password()/get_password_hash() 从未被调用。
backend/app/api/v1/auth.py | backend/app/models/user.py | backend/app/core/security.py
CRITICAL
SQL 注入风险
chart_service.py 过滤参数值直接拼接到 SQL 字符串，仅做单引号转义。trigger_scheduler.py / temp_table_manager.py 构造 SQL 使用字符串插值。
backend/app/services/chart_service.py | backend/app/services/pipeline/trigger_scheduler.py | backend/app/services/pipeline/temp_table_manager.py
CRITICAL
JWT Secret 硬编码入库
.env 文件包含 SECRET_KEY 并提交到仓库。若仓库公开，任何人可伪造 JWT Token。
backend/.env
CRITICAL

🟠 高优先级问题 (High)

God Class — PipelineEngine
engine.py 4069行/190KB，包含 SQL 生成、验证、类型推断、批处理、增量更新、列投影、拓扑排序等所有逻辑。极难维护和测试。
backend/app/services/pipeline/engine.py
HIGH
User.userID 无自增 — 竞争条件
User.userID 缺少 autoincrement=True，使用 SELECT MAX(userID)+1 手动生成，并发创建用户时存在竞态条件。
backend/app/models/user.py
HIGH
异常处理不一致
Services 统一 raise Exception(str(e))，丢失原始异常类型。PermissionError 使用 Python 内置类型而非自定义异常。
backend/app/services/*.py
HIGH
前端 console.log 泄露
authService.ts 大量 console.log 输出登录凭据、Token 等敏感信息。生产环境应移除。
frontend/src/services/authService.ts
HIGH
前端 mysql2 依赖暴露
package.json 包含 mysql2 依赖，前端不应直接连接数据库，存在安全隐患。
frontend/bi-dashboard/package.json
HIGH

🟡 中等问题 (Medium)

datetime.utcnow() 已弃用
多个文件使用 datetime.utcnow()，Python 3.12+ 已弃用，应改用 datetime.now(timezone.utc)。
backend/app/services/*.py
MEDIUM
硬编码默认值
图表查询 LIMIT 10000、缓存 TTL 3600s、批处理 5000 条等全部硬编码，无法通过配置调整。
backend/app/services/chart_service.py | pipeline/engine.py
MEDIUM
引擎释放不一致
trigger_scheduler.py 每次 poll 后 dispose() 引擎，与 chart_service 的缓存策略矛盾，丧失缓存优势。
backend/app/services/pipeline/trigger_scheduler.py
MEDIUM
